# 安全、幻觉与风险治理

## 幻觉治理

本项目把“可追溯依据”作为风险落库门槛，而不是把模型文本直接当作结论：

1. 规则引擎先执行硬约束，关键词、正则和数值规则结果携带 `source_type=rule`、规则 ID 和规则名称。
2. RAG 只检索 `enable=1` 的知识库条目，结果携带条目 ID、分类和参考编号。
3. 没有检索依据的模型风险不落库；模糊表述（如“另行协商”“待定”“无法判定”）输出人工审阅提示。
4. 前端详情页展示风险、原文条款、依据和建议，法务必须逐条选择“属实/不属实”后才能提交整体复核。
5. 报告固定附带免责声明，明确 AI 输出不具备法律效力。

## 文件与输入安全

| 风险 | 控制措施 | 失败行为 |
| --- | --- | --- |
| 扩展名伪造 | 仅允许 `.pdf`、`.docx`、`.txt`、`.md` | 返回 400，不写入业务记录 |
| 伪造 PDF | 校验 `%PDF-` 文件签名 | 返回 400，拒绝解析 |
| 恶意 DOCX | 校验 ZIP 结构、必需 XML 和解压体积 | 返回 400/413 |
| 空文件/二进制文本 | 空内容和 NUL 字节检查 | 返回 400 |
| 超大上传 | 默认 20MB 上限，可通过 `.env` 调整 | 返回 413 |
| 路径穿越 | 文件名净化、随机前缀、配置路径禁止绝对路径和 `..` | 返回 422 |
| 恶意内容 | 生产环境应在解析前接入杀毒/沙箱扫描 | 扫描失败时阻断解析 |

## 身份、权限与数据隔离

- JWT 使用 HMAC-SHA256 签名和过期时间；每次加载工作台通过 `/api/auth/me` 同步账号状态。
- 密码创建和重置均使用 bcrypt 哈希，数据库不保存明文密码。
- `uploader` 只能查询自己上传的合同，不能调用复核和管理员接口。
- `legal_reviewer` 可查看全部合同和执行复核，但不能访问系统设置。
- `admin` 可管理规则、知识库、用户和系统参数；后端 `/api/admin/*` 路由依赖强制返回 403。
- 最后一个启用管理员不能被禁用、降级或删除，避免系统失去管理入口。

## 生产加固清单

- 使用密钥管理服务生成 `JWT_SECRET`，禁止把 `.env` 提交到 Git。
- 通过 HTTPS 反向代理暴露服务，限制 CORS 来源和管理端网段。
- 将 `data_storage` 放在加密磁盘或私有对象存储，设置备份和保留周期。
- 接入杀毒、DLP、审计日志、速率限制和登录失败锁定。
- 对 Chroma、LLM、SQLite 的网络访问做最小权限隔离；不要把内部模型地址暴露给浏览器。
- 上线前替换演示账号密码，清空演示合同和数据库。
