# 失败场景处理手册

## 用户可见失败矩阵

| 场景 | 系统处理 | 用户提示/恢复动作 |
| --- | --- | --- |
| Python/Node 缺失 | 启动脚本提前检查并退出 | 安装 Python 3.10+、Node.js 后重试 |
| `.env` 缺失 | 自动复制 `.env.example` | 修改 `JWT_SECRET` 和服务参数 |
| 8082/5173 被占用 | 启动前端口探测 | 关闭占用进程后重新启动 |
| 依赖安装失败 | 保留原进程状态并退出 | 检查网络、镜像和依赖文件 |
| PDF/DOCX 校验失败 | 不进入解析流程 | 重新导出有效文件 |
| 文档解析失败 | 记录“解析失败”和错误信息，保留原文件 | 修复文件后点击重新解析 |
| LLM 超时/不可用 | 规则结果和已完成结果保留，返回超时提示 | 重试审查或人工处理 |
| Chroma 不可用 | 自动回退 SQLite 关键词检索 | 检查 Chroma，恢复后全量同步 |
| 知识库同步失败 | 数据库变更仍可追踪，记录同步错误 | 修复向量服务后执行同步/重试 |
| 风险无来源依据 | 审查结果被拦截，不写入风险清单 | 转人工审阅，不采信无依据结论 |
| 模糊条款 | 生成“无法判定，请法务人工审阅”关注项 | 法务补充明确时间、金额和责任边界 |
| 非法角色/过期 JWT | 返回 401/403，不泄露资源详情 | 重新登录或联系管理员 |
| 上传者访问他人合同 | 数据层查询条件拦截 | 仅查看本人合同 |
| 管理员误删 | 前端二次确认，后端按 ID 校验 | 取消操作或从备份恢复 |
| 报告生成失败 | 降级为 Markdown 下载 | 检查 PDF 依赖后重试 |
| 页面关闭 | 心跳失效后脚本清理前后端进程 | 重新运行启动脚本即可恢复 |

## 运维排查顺序

1. 访问 `GET /api/health` 确认 API 进程存活。
2. 检查启动控制台中的端口、依赖和“部分业务接口待实现”提示。
3. 查看合同详情中的 `parse_error`、状态时间线和审查 `warnings`。
4. 检查 `.env` 中 `CONTRACT_REVIEW_DB`、`CHROMA_ENABLED`、`MAX_UPLOAD_MB`。
5. 不要直接修改 SQLite 业务记录；优先使用管理员接口或备份恢复。

## 已知限制

- 扫描 PDF 目前只提示 OCR 为扩展能力，不会伪造文本结果。
- 默认审查器是确定性基线，不代表完整法律意见；接入 LLM 后仍必须保留来源门禁和法务复核。
- `CHROMA_ENABLED=false` 是演示默认值，生产环境应验证向量服务可用性和备份策略。
